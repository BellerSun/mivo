# Mivo

macOS 原生菜单栏应用：通过 USB 连接的大疆 Mic Mini 2 发射器配对键（接收器通过 USB 连接），控制千问「按住监听」（右 Command）。

- 短按一次开始监听，再短按结束。
- 默认支持结束后 3 秒内再按发送回车；可在设置中关闭，立即生效。
- 点击菜单栏图标打开状态面板，查看状态、暂停或开启控制。
- 启动或再次打开应用默认显示首页状态面板；设置页通过「设置」入口主动打开。
- 悬浮提示常驻显示下一次短按配对键的动作：蓝色麦克风开始监听、橙色停止符号结束监听、绿色回车发送。发送窗口显示 3 秒倒计时和进度，超时自动恢复开始监听；关闭「结束后再按发送」时跳过发送状态。
- 悬浮提示不抢键盘焦点，可以拖动并记住位置；断连、暂停或权限不足时灰色显示原因。开发模式明确标为模拟，不展示虚构的音量波形。
- 默认采用 44 × 44 的迷你图标方块，发送窗口以沿圆角外框缩短的环线倒计时，不显示文字或秒数。设置页可切换「标准／迷你」或关闭悬浮提示，立即生效并保存；隐藏提示不会暂停麦克风控制。迷你版不可用时显示灰色原因图标，开发模式另有 DEV 标记。
- 悬浮窗整块区域均可左键拖动，松开后保存位置。悬停时提亮并显示手形光标，按下和拖动时提供轻微按压反馈；右键菜单仅含「打开主窗口」与「退出」。
- 暂停会自动保存，重连设备、重新激活或重启应用都不会取消暂停。
- 设置和诊断日志独立打开；退出入口在面板右下角「更多操作」菜单。
- 菜单栏图标被刘海遮挡时，在设置页底部点击「显示面板」，即可打开同一套设备面板。

## 构建与启动

需要 macOS、Xcode Command Line Tools（`xcode-select --install`）、Python 3，以及可通过 PATH 找到的 OpenSSL 或系统 LibreSSL。应用运行时只依赖系统框架；构建脚本还会使用 Python 和签名工具。首次设置会在登录钥匙串创建本机代码签名身份，可能需要你确认钥匙串操作。

克隆仓库并进入项目目录后，先配置签名：

```bash
./scripts/setup-signing.py
```

首次在新电脑构建前，先运行 `./scripts/setup-signing.py` 配置本机固定签名。先退出正在运行的 Mivo，再安装新版。安装脚本会拒绝覆盖运行中的应用；完全相同的构建会跳过替换。

```bash
./scripts/build-and-install.sh
open /Applications/Mivo.app
```

安装目标：`/Applications/Mivo.app`。使用系统 Swift 编译器，构建当前电脑架构的应用；部署目标为 macOS 13。该目标不代表已在所有 macOS 版本或 Intel / Apple Silicon 设备上完成实测，反馈时请注明系统和架构。

只构建并验证签名、不安装或启动应用：

```bash
./scripts/build-and-install.sh --build-only
```

产物位于 `.build/Mivo.app`。图标只维护 `Assets/Logo/mivo.svg`，打包时自动生成 ICNS 到 `.build/icons/`。按需导出 PNG、ICO 等格式的方法见 [图标说明](Assets/Logo/README.md)。

## 首次使用

通过菜单栏面板进入「设置」，为 Mivo 开启辅助功能与输入监控。原有「设备与权限」两行显示当前进程的真实权限状态，每 2 秒自动检测。开发模式的模拟权限不会冒充真实权限。

权限帮助收纳在「设备与权限」标题旁的问号弹层中，提供重新检测、当前应用路径、在访达中显示和重启。若系统开关与检测结果不一致，先重启；仍不一致时移除旧 Mivo，再添加 `/Applications/Mivo.app`。弹层也提供「修复辅助功能授权」，须用户明确确认后才仅重置 Mivo 的辅助功能授权，不修改其他应用或输入监控。

千问语音输入需设为「按住监听」，快捷键为右 Command。接收器需通过 USB 连接电脑。

## 设置

「结束后再按发送」默认开启，修改立即生效并自动保存，重启后保留。关闭后，结束监听后再次按键会直接开始新一轮监听。

## 开发模式（无需外设）

在设置页右下角的 **Mivo 1.0 版本号上连续点击 5 次**，开启开发模式。进入后会明确显示 DEV 标记；点击「退出开发模式」恢复真实设备。开发模式不会保存到下次启动。

也可以先退出正在运行的 Mivo，再带参数启动：

```bash
open /Applications/Mivo.app --args --dev
```

开发模式支持：

- 模拟「已连接且已授权」「未连接」「需要授权」。
- 点击「按一下接收器」走与真实 HID 输入相同的状态机和 Command 拦截逻辑。
- 验证开始、结束、3 秒发送窗口、即时开关、暂停和断连恢复。
- 打开「预览菜单栏面板」，在独立窗口中调试与菜单栏相同的界面。
- 在诊断日志中查看按键的拦截、放行及模拟回车输出。

开发模式不会修改真实设备映射、打开硬件监听、安装系统按键拦截、自动请求真实权限或向其他应用发送按键。只有手动点击真实系统权限的「去开启」才会请求授权。它用于验证逻辑和界面；真实外设事件的时序、系统权限及千问联动仍需连接设备验证。

## 行为检查

```bash
./scripts/test.sh
./scripts/test-floating.sh
```

直接编译生产模型并使用隔离的偏好设置运行模拟测试，不启动应用、不改动个人设置。覆盖监听与发送、窗口超时、设置持久化、暂停保持、断连/权限恢复及模式切换。

悬浮窗检查使用独立进程和隔离偏好设置，验证不抢键盘焦点、位置保存与恢复，以及显示器变化后的越界位置恢复。

## 固定本机签名

构建使用保存在登录钥匙串中的固定本地代码签名证书 `Mivo Local Development`，不再使用临时签名。证书只用于本机开发，不是面向其他电脑分发的 Developer ID，也不调整系统的根证书信任设置。

- 公共配置位于 `~/.config/mivo/signing.json`，固定证书 SHA-1 指纹和钥匙串路径。
- 私钥保存在登录钥匙串中，不写入仓库；生成时的临时密钥和导入文件会删除。
- 所有更新沿用同一张证书与原 bundle ID。证书或配置丢失时构建报错，禁止自动生成新身份或退回临时签名。
- 从旧临时签名迁移到固定身份时，需要重新添加当前 Mivo 并授权一次。之后更新以同一证书身份识别；系统撤销授权、删除证书或换证书不在此保证范围内。
- 相同源码使用构建和二进制校验缓存，避免无意义的重新签名；保留系统启动所需的 Mach-O UUID。

首次设置（已有身份时只复用，绝不自动换证书）：

```bash
./scripts/setup-signing.py
```

签名回归测试：

```bash
./scripts/test-signing.sh
```

测试编译两份内容不同的代码，验证它们互相满足同一个证书绑定的 designated requirement，并拒绝只有相同 bundle ID、没有相同证书的签名。

历史维护记录：2026-11-07 曾在维护者本机完成固定签名迁移及一次不同 CDHash 更新后的权限继承验证。这只说明该次设备与系统环境的结果，不代表当前改动、其他电脑或所有系统版本均已通过 TCC 实测。签名回归测试验证签名身份约束，不能替代真实系统授权验证。

如果将来改用 Developer ID，使用明确的证书指纹和钥匙串路径覆盖 `MIVO_SIGNING_IDENTITY`、`MIVO_SIGNING_KEYCHAIN`。切换身份前须规划授权迁移。更换电脑前应通过钥匙串安全备份原签名身份，勿重新生成另一张同名证书。

## 配对键指引

状态面板使用 SwiftUI 绘制 DJI Mic Mini 2 发射器「实物质感」示意：灰色圆角边框、深色颗粒磁吸前盖，以及侧面配对键和电源键。配对键以蓝色高亮，提示随开始、结束及 3 秒发送窗口变化。

真实 HID 按下/松开会同步驱动图上配对键的下沉、高亮及回弹；短按至少保留 180 毫秒反馈，便于看清。监听状态保留淡蓝轮廓；不展示没有采集依据的音量波形或电量。系统开启「减少动态效果」时取消位移动画。

开发模式下点击图上配对键与「按一下接收器」按钮共用模拟流程。正常模式点击图示只打开操作说明，不会向其他应用发送按键。操作对象是麦克风发射器侧面的配对键，接收器仍需 USB 连接电脑。


## 兼容性与已知限制

- 当前识别的接收器 USB Vendor ID / Product ID 为 `0x2CA3 / 0x4011`，操作对象为 DJI Mic Mini 2 发射器的配对键。其他型号、固件和连接方式尚未建立验证矩阵。
- 千问需要支持并配置「右 Command 按住监听」。目前没有记录完整的千问版本兼容矩阵，升级后需实际验证。
- Mivo 不检查当前前台应用。监听快捷键和「结束后再按发送」的回车会作用于当前输入环境，回车可能提交当前应用中的内容；使用前确认输入焦点，或在已有设置中关闭再按发送。
- 控制期间仅修改匹配接收器服务的音量增减键映射，保留其他映射；正常暂停、退出或启动失败时尝试恢复每个服务的原映射。若检测到其他工具已修改映射，保留外部设置，不用旧快照覆盖。
- 映射快照只在当前进程内保存。强制结束或崩溃无法保证执行恢复；拔插接收器后再检查映射。设备移除后不把旧快照写入新连接的服务。恢复失败会记入诊断日志。

## 隐私与权限

Mivo 自身不采集或保存音频、不执行语音识别，没有网络上传或遥测逻辑。语音由你配置的千问处理，其数据行为需以该应用的说明为准。

辅助功能和输入监控用于读取目标设备事件、拦截右 Command 修饰键事件及发送模拟按键；Mivo 不记录输入正文或剪贴板。偏好设置仅在本机保存控制开关、发送选项、悬浮样式及位置。诊断日志最多保留 500 条于进程内存，包含控制动作、时间、权限状态和错误；诊断窗口还显示电脑名称与系统版本，权限帮助显示应用路径。提交日志或截图前请遮盖姓名、电脑名、路径及其他个人信息。

签名私钥仅保存在本机钥匙串。不要提交签名配置、私钥、证书导出包或完整本机诊断文件。安全问题的反馈方式见 [SECURITY.md](SECURITY.md)。

## 源码构建与发布版

当前流程用于自行编译、自行签名和本机安装。不同电脑首次配置会得到各自的本地身份，不应共享维护者的签名私钥，也不要把自己的本机签名产物当成经过 Developer ID 签名和公证的通用发布版。

对外提供安装包前，需要另行建立 Developer ID 签名、公证、版本校验与真实设备测试流程。不要通过关闭系统保护或修改 TCC 数据库绕过安装和授权问题。

## 卸载与反馈

先从 Mivo 菜单退出，使应用有机会恢复设备映射，再删除 `/Applications/Mivo.app`。需要清理系统授权时，可在系统设置的辅助功能与输入监控中手动移除 Mivo。卸载不会自动删除偏好设置或签名身份；计划重新安装或更新时应保留原身份，不要为排障重建同名证书。

普通问题可提交 GitHub Issue，附上 Mivo 版本、macOS 版本、CPU 架构、设备型号及固件、千问版本、复现步骤、预期和实际行为，并注明真实设备或开发模式。不要公开密钥或未脱敏诊断信息。贡献流程见 [CONTRIBUTING.md](CONTRIBUTING.md)。
